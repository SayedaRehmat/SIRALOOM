| ID | Severity | Area | Evidence / root cause | Correction | Verification |
|---|---|---|---|---|---|
| A1-AUTH-001 | High | Authentication environment isolation | `get_current_principal()` allowed implicit development identity when Firebase auth was optional and `APP_ENV` was anything except `production`. Shared staging/preview could therefore accept unauthenticated requests. | PR #185 restricts implicit identity to explicit `development` or `test`; other environments fail closed with HTTP 401. | Merged as `5735d57652ff5d5c12a798863471db99ade72e7a`; CI run #1410 passed all three jobs. |
| A1-AUTH-003 | High | Single-use invitation acceptance | `backend/app/api/v1/auth.py:accept_organization_invitation` selected a PENDING invitation without a row lock, so two concurrent accepts could both observe PENDING and provision membership state before either commits. | Added `SELECT ... FOR UPDATE` on the invitation lookup so acceptance and the ACCEPTED status transition serialize in the same transaction; added a PostgreSQL race integration test expecting one acceptance and one HTTP 409. | CI run #1432 passed the PostgreSQL integration job. |
| A1-AUTH-004 | High | Cross-invitation identity provisioning | `_provision_organization()` and `accept_organization_invitation()` checked for an existing Firebase subject without a shared concurrency boundary. Distinct invitation tokens could race and create duplicate user rows for one subject. | Added a PostgreSQL transaction-scoped advisory lock keyed by SHA-256 of the verified subject in both provisioning paths; added an integration test that accepts distinct invitations for the same identity concurrently. | CI run #1432 passed the PostgreSQL integration job. |
| A1-AUTH-002 | Medium | Membership authority | Resolver reads active membership and derives the effective role from membership, not the user role. Regression tests for stale role divergence, suspended/revoked membership, and unknown roles were absent from this audit batch. | Added `tests/test_principal_membership_authorization.py` covering role authority, suspended/revoked memberships, and invalid roles. | CI run #1432 passed backend tests. |
| A3-CASE-001 | Medium | Duplicate case creation | The pre-insert existence query and insert were not atomic. The database unique constraint prevented duplicate rows but the losing concurrent request raised an unhandled `IntegrityError`. | PR #186 rolls back and returns the matching tenant-scoped case when another request won the insert; unrelated errors are re-raised when no matching case exists. | Merged as `16d2b931beb56a09f2a6eedfeb44b42d6b15bcef`; CI run #1411 passed all three jobs. |
| A3-CASE-002 | Medium | Real concurrency evidence | The original PR #186 unit test used a mocked session; it did not demonstrate a simultaneous PostgreSQL insert race. | Added a barrier-synchronized test to `tests/integration/test_analysis_dispatch_postgres.py` asserting one durable case, one `CASE_CREATED` audit event, and responses `created=true/false`. | CI run #1432 passed the PostgreSQL integration job. |
| A4-WORKFLOW-001 | High | Annotation-stage resource failure and replay | `backend/app/workflows/variant.py:run_variant_analysis` had unreachable duplicate annotation-resource handling after a `return`; resource failure handling was scoped around initialization rather than the full annotation-stage body. | PR #187 removes the unreachable duplicate code and scopes resource-failure handling around the annotation stage. `tests/test_actual_annotation_stage_redelivery.py` injects worker loss after durable annotation-row commit and verifies Celery redelivery reconciles persisted rows and checkpoints without repeating the provider request. | CI run #1432 passed backend tests; this deterministic test is not live-provider or clinical truth-set validation. |
| A1-AUTH-005 | High | Membership mutation authorization race | Membership mutation previously checked the actor role before acquiring the tenant lock and loaded the target before locking, allowing stale role/status decisions while waiting. | PRs #189 and #192 acquire the tenant advisory lock first, re-read and row-lock the actor's active membership, derive authorization from that locked role, and row-lock the tenant-scoped target before applying active-admin invariants. | PostgreSQL integration test races two administrators attempting to revoke one another; exactly one succeeds and one active administrator remains. Full CI run #1452 passed all three jobs. |
| A3-CASE-003 | Medium | Concurrent case metadata updates | Concurrent metadata updates could read the same prior case state before recording audit and reanalysis-candidate changes. | PR #190 locks the case row before reading prior state and keeps metadata, audit, and reanalysis-candidate writes in one transaction. | `tests/test_case_update_serialization.py`; CI run #1440 passed all three jobs. This is a row-lock contract test, not a load test. |
| A3-CASE-004 | High | Specimen identity collision | The database did not enforce unique specimen identifiers within a case, allowing concurrent requests to register the same specimen identity. | PR #191 adds `uq_specimen_case_identifier`, a migration preflight that refuses to alter/delete duplicate legacy records, and an HTTP 409 conflict response after rollback. | Migration 0047 and duplicate-conflict regression passed CI run #1442. Before applying migration to a populated laboratory database, resolve any reported duplicate `(case_id, specimen_identifier)` records explicitly. |
| A4-WORKFLOW-002 | High | Normalization operational retry | Unexpected normalization-stage storage/database errors were marked terminally FAILED even when they represented recoverable infrastructure failures. | PR #193 routes `SQLAlchemyError` and artifact-storage `OSError` through durable `RETRYING` state, `next_step=normalize`, audit event, and bounded Celery retry. | `tests/test_normalization_retry_contract.py`; CI run #1449 passed all three jobs. Full actual normalization stage-body crash/replay remains unproven. |

| A1-AUTH-006 | High | Invitation revocation versus acceptance | The single-use invitation lifecycle had no serialized revoke transition to race against acceptance. | PR #200 adds tenant-scoped revocation, active-actor revalidation, role hierarchy, `revoked_at`, and an audit event; acceptance and revocation lock the same invitation row. | PostgreSQL integration test proves one transition wins and the other receives HTTP 409; CI run #1469 passed all jobs. |
| A1-AUTH-007 | High | API authentication and shared tenant boundary coverage | The audit lacked an executable inventory check for server principal resolution on every non-public API route and a shared-accessor matrix for cross-tenant object hiding. | PR #197 adds the FastAPI route dependency audit; PR #198 tests case, analysis, artifact, and report accessors for same/foreign tenants; PR #201 exhaustively tests shared role policies. | CI runs #1460, #1462, and #1468 passed all jobs. Worker-entrypoint and route-specific authorization/state coverage remain distinct. |
| A3-CASE-005 / A7-REVIEW-001 | High | Concurrent classification approval version allocation | Approval created a new immutable classification row while locking only the current row, allowing concurrent approvers to allocate the same next version. | PR #196 locks the durable Analysis row before reading the latest classification and allocating the next version. | PostgreSQL race test proves concurrent approvals converge on one version-2 classification, one review action, and one audit event; CI run #1458 passed all jobs. |
| A4-WORKFLOW-003 | High | Duplicate normalization artifacts on replay | A worker could persist normalized VCF/index artifacts and die before the stage-success checkpoint; re-execution used fresh artifact IDs and could create duplicate rows. | PR #199 uses deterministic artifact IDs per analysis/output and reuses artifacts only when content hash, size, storage existence, and scientific provenance match; mismatched bytes fail closed. | `tests/test_normalization_artifact_idempotency.py`; CI run #1464 passed all jobs. This covers normalization artifact persistence, not all-stage replay. |
| A8-REANALYSIS-001 | Medium | Incremental reanalysis provenance reuse | Existing tests did not verify that incremental replay copies only upstream observations and preserves exact resource/request/response provenance. | PR #195 tests reuse boundaries for population, evidence, and ACMG-rule changes, including provider/resource versions and fingerprints. | `tests/test_reanalysis_reuse_provenance.py`; CI run #1456 passed all jobs.
